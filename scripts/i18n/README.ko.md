# 업스트림 업데이트 후 한국어·영어 패치 유지하기

영문 상세: [README.md](README.md). 이 포크의 원격 저장소는
`https://github.com/sehoon123/ARTEX.git`입니다.

## 1. 업데이트를 별도 브랜치에서 병합

작업 폴더가 깨끗한지 먼저 확인하세요. 병합과 충돌 해결은 자동화하지 않습니다.
아래 명령은 저장소 루트에서 실행합니다.

```bash
git status --short
# 처음 복제했다면 한 번만 등록:
# git remote add upstream https://github.com/Autumn-27/ARTEX.git
git fetch upstream
git switch -c upstream-update-$(date +%Y%m%d-%H%M)
git merge upstream/main
# 충돌 해결 후 아래 번역 절차 진행
```

기존 `tr()` 호출이 있는 줄과 업스트림의 새로운 로직을 함께 보존해야 합니다.
충돌을 무조건 한쪽 버전으로 덮어쓰지 마세요. 키·ID·상태값·정규식·모델 프롬프트는
번역 대상이 아닙니다.

## 2. 누락 확인 → 번역 → 한 번에 검증

필요 도구: **Node 22 이상**, `go.mod`에 지정된 **Go**, 기존 프론트엔드 의존성.

```bash
cd web
npm ci
npm run i18n:check
# 검사 실패는 새로운 UI 문구 또는 내장 메타데이터 변경을 뜻할 수 있습니다.
```

### 내장 이름·설명 변경이 보고된 경우

먼저 Go 소스의 변경을 읽으세요. 실제 실행 도구나 서버는 실행하지 않습니다.

```bash
npm run i18n:catalog
```

이 명령은 **검토한 소스 기본값의 표시용 스냅샷만 갱신**합니다. DB나 백엔드,
기존 번역은 수정하지 않습니다. 새 도구의 `builtin.tool.<key>.summary`가 없으면
스냅샷을 갱신한 뒤에도 실패하며 누락된 키를 표시합니다. 두 사전에 짧은 UI 요약을
작성하세요. 모델이 사용하는 긴 설명/지시문을 바꾸는 작업이 아닙니다.
기존 요약도 소스의 의미 변화에 맞는지 검토해야 합니다.

### UI 번역 추가

```bash
npm run i18n:extract
# API를 사용하려면 직접 설정한 자격 증명 필요:
# export OPENAI_API_KEY=...
# 또는 export ANTHROPIC_API_KEY=...
npm run i18n:sync
npm run i18n:verify
```

`i18n:sync`는 누락된 항목만 번역하고 표시 위치를 감쌉니다. 기존 수동 번역은
덮어쓰지 않습니다. 연결/응답/플레이스홀더 검증 실패는 성공으로 처리하지 않습니다.
유효한 번역 API가 없다면 `web/src/lib/i18n/en.json`과 `ko.json`에 누락 항목을 직접
추가한 뒤 `npm run i18n:wrap` → `npm run i18n:verify`를 실행하세요.
`{n0}` 같은 자리표시자는 개수까지 유지해야 합니다.

`i18n:verify` = 회귀 테스트 + 번역/내장 메타데이터 검사 + 실제 정적 프론트엔드 빌드.
포크의 `localization-check` GitHub Actions도 같은 명령을 실행합니다.
단, 검사 통과가 모든 동적 화면의 번역이나 번역 품질까지 보장하지는 않습니다.

## 3. 웹에서 확인할 것

EN과 KO 각각에서 데이터가 있는 목록, 검색, 상세 화면, 버튼, 선택 메뉴, 툴팁,
팝업, 폼 검증과 알림을 확인하세요. 특히 새 기능과 API로 내려오는 표시 항목은
소스 문구 검사만으로 빠질 수 있습니다.

- 도구/Agent/규칙의 저장 요청에서 원래 ID·설명·스키마·기본값·규칙이 유지되는지 확인.
- 실행/삭제/외부 연결 버튼 검사는 실제 대상이 아닌 격리된 로컬 모의 API로 수행.
- 사용자/외부 MCP/Skill 콘텐츠, 보고서·로그·모델 출력, 편집 가능한 원문은 자동 번역하지 않음.
- 오래된 DB 설명이나 사용자가 편집한 기본값은 현재 스냅샷과 일치하지 않으면 원문으로 표시.
- 명령 차단 규칙 이름은 원문 유지(중국어 예약 이름 포함). API에 내장 출처 필드가 없고 사용자도 같은 이름을 쓸 수 있어 이름만으로 번역하지 않음.
- 내장 자산 규칙 설명은 내장 여부와 종류·패턴·설명이 모두 소스 기본값과 일치할 때만 번역.

## 4. 포크 버전을 빌드·설치

**업스트림 Docker 이미지나 업스트림 릴리스에는 이 포크의 패치가 없습니다.**
기존 프로그램의 업스트림 자동 업데이트는 번역 패치를 잃게 할 수 있으므로,
패치를 유지하려면 병합·검증된 포크에서 다시 빌드해야 합니다.

검토한 브랜치를 승인 후 자신의 포크에 반영하고:

1. 포크의 GitHub → **Actions → build-binary → Run workflow**.
2. WSL용 Linux x86-64 파일이 필요하면 targets를 `linux/amd64`로 지정.
3. 릴리스를 만들지 않으려면 tag를 비워 둠.
4. 성공한 실행의 `artex-binaries` 아티팩트에서 ZIP과 `SHA256SUMS` 다운로드.
5. 체크섬 확인 후 서비스를 중지하고 기존 바이너리를 백업해 새 파일로 교체.
   설정·DB·데이터 디렉터리는 덮어쓰지 않음.

이 워크플로는 EN/KO 정적 UI를 Go 바이너리에 포함하도록 구성되었습니다.
로컬 `web/out`만 빌드해도 기존 바이너리의 내장 UI가 바뀌는 것은 아닙니다.
Docker는 필요 없지만 PostgreSQL은 필요합니다. **WSL1의 실제 실행/PTY/DB 연결은
별도로 검증해야 하며, 프론트엔드 검사 통과로 호환성을 보장하지 않습니다.**
