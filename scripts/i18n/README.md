# Korean/English localization maintenance

[한국어: 업스트림 업데이트 절차](README.ko.md)

UI source strings and stable `builtin.tool.*.summary` IDs are dictionary keys in
`web/src/lib/i18n/{en,ko}.json`.
The browser locale is selected in the sidebar menu and saved as `artex_locale`.
Switching asks for confirmation, then reloads to refresh module-level label maps;
cancelling leaves both locale and storage unchanged. The provider waits
for client mount before showing translated content, so static HTML and initial
hydration agree; it also updates `<html lang>`. Blocked browser storage produces a
visible error instead of reloading into the wrong language.

**Translate display text, not model inputs.** When upstream improves prompts or
model-facing tool instructions, accept its **new originals**; neither freeze the old
Chinese text nor translate it. Prompt-language changes need a separate behavior/quality
comparison. For an agent-assisted update, use the [copyable request](#request-for-your-next-ai-assisted-update).

## After an upstream merge

Run from the **repository root**, only when the update/merge is approved. Stop if
the tree is dirty; preserve existing work first and confirm local `main` is the
intended fork baseline.

```bash
git status --short
git remote -v                        # origin=sehoon123/ARTEX; upstream=Autumn-27/ARTEX
git switch main
# Once after cloning: git remote add upstream https://github.com/Autumn-27/ARTEX.git
git fetch upstream
git rev-parse HEAD upstream/main      # record both SHAs
git diff --stat HEAD...upstream/main
git switch -c upstream-update-$(date +%Y%m%d-%H%M)
git merge upstream/main              # explicit user operation, never automated
# If conflicted, STOP and follow the conflict section before continuing.
cd web
npm ci
npm run i18n:check
# ONLY after reviewing reported backend display-default changes:
# npm run i18n:catalog                # refreshes reviewed snapshots, NOT translations
export OPENAI_API_KEY=...             # or ANTHROPIC_API_KEY
npm run i18n:sync
npm run i18n:verify                   # tests + checks + static UI export, NOT a binary build
# Inspect populated EN/KO screens and git diff before committing/publishing.
```

The scripts resolve their paths relative to themselves, not the shell directory.
Node 22+ and the existing `web/node_modules/typescript` are required (`cd web && npm ci`).
No additional package or `rg` executable is required. Go (the version required by
`go.mod`) is also needed for the source-only built-in metadata check.

Without a working provider, use `npm run i18n:extract`, fill missing entries in
both dictionaries manually, then `npm run i18n:wrap` and `npm run i18n:verify`.
The fork's `localization-check` workflow runs verification on pushes/PRs; it does
not translate, merge upstream or publish anything.

## Resolving conflicts

List unresolved files with `git diff --name-only --diff-filter=U`. After reviewing
and resolving each file, stage only those files and run `git merge --continue`.
To cancel an **unfinished** merge, preserve any resolution work you need first,
then use `git merge --abort`; it does not undo an already completed merge.
Never blanket-accept ours/theirs for entire files.

| Location | What must survive |
| --- | --- |
| UI `.tsx` | Upstream logic plus display `tr()` calls. Chinese source text is the key, so unchanged ordinary JSX/display attributes can be rewrapped after dictionary completion. This is not whole-file restoration. |
| API labels, dates, statuses | `builtin-labels.ts` display helper calls/imports, `getLocale()`, and `statusMeta()` display translation are NOT regenerated by wrap. Compare tools/Agents/chat/MCP/Skills/tooltips and their data flows. |
| `en.json` / `ko.json` | Keep needed keys from both sides and manual translations. Translate values, not Chinese keys; preserve placeholder occurrence counts. Resolve duplicate keys/invalid JSON rather than overwriting one side. |
| Metadata JSON | Review merged Go source, then refresh with `i18n:catalog`; do not choose an arbitrary snapshot. |
| Package/workflows/READMEs | Retain upstream dependency/feature updates AND fork i18n scripts, checks, and EN/KO instructions. Resolve lockfile mismatches. |

Before promoting the update branch, inspect from the root:

```bash
git diff main -- web/src scripts/i18n web/package.json .github/workflows README.md README.ko.md
```

Not all dynamic display-helper call sites have regression coverage. Passing checks
cannot prove those patches survived. Preserve IDs, stored values, comparisons,
regexes, schemas and model inputs; never indiscriminately translate API values.

## Commands

- `extract.mjs`: list keys missing from **either** dictionary, including already
  wrapped calls. Uses TypeScript's parser, not line-based regexes. Missing keys do
  not cause a nonzero exit; use check/verify as the gate. New builtin tool-summary
  IDs are reported separately by the catalog check, not generated by extract/sync.
- `translate.mjs [en] [ko]`: fill only missing entries; preserve manual translations.
- `wrap.mjs`: apply validated display edits; `--check` performs the same inventory
  and fails on missing dictionaries, pending wraps, or unsupported client boundaries.
- `sync.mjs`: translate, then wrap. Any failed stage returns nonzero.
- `test.mjs`: isolated regression tests, including a local HTTP-compatible provider
  and populated built-in display components. Tests never use real API credentials,
  modify production dictionaries, or run tools displayed by the application.
- `catalog-check.mjs` (included in `npm run i18n:check`): checks exact-source
  snapshots, tool summaries, builtin Agents/variable help and reserved rule/asset
  labels in both dictionaries. `--update` (`npm run i18n:catalog`) explicitly refreshes
  reviewed snapshots; it can still fail on missing translations after writing.
  Review existing summaries for changed meaning and author short summaries for new
  `builtin.tool.<key>.summary` IDs in BOTH dictionaries. It never edits backend data.
- `catalog.go`: uses Go's parser to inventory metadata from the known tool factories
  and `actool.Spec` literals. It does not import or execute ARTEX or its handlers.
  The metadata check fails when known source defaults differ from
  `web/src/lib/builtin-tool-descriptions.json` or `builtin-metadata.json`. Summary IDs
  are derived from exact-known tool keys, so adding a tool does not require another
  label map. Agent positional declarations, global variable descriptions and reserved
  name literals are also inventoried. Unsupported changed declarations fail; entirely
  new factory/declaration/name-expression styles still require manual review.

Provider selection: `ANTHROPIC_API_KEY` first (default model
`claude-haiku-4-5-20251001`); otherwise `OPENAI_API_KEY` (default `gpt-4o-mini`).
Override with `I18N_MODEL`; OpenAI-compatible endpoints can use `I18N_BASE_URL`.
`BATCH` is a positive integer (default 40), `LIMIT` a nonnegative per-locale cap,
and `I18N_TIMEOUT_MS` a positive timeout (default 60000). Provider/model availability
must be verified separately with your credentials. The previous Haiku 3.5 default
was [retired on February 19, 2026](https://platform.claude.com/docs/en/about-claude/model-deprecations).

## Check failures: next action

Run npm commands from `web/`. `i18n:check` stops at the first failed stage; rerun
after fixing it to expose later catalog issues.

| Message/situation | Next action |
| --- | --- |
| `missing en/ko` | Extract → fill both dictionaries manually or with a provider → wrap. |
| `file(s) need wrapping` | Run `i18n:wrap`, then review the diff. |
| `review these display/key or nested-expression semantics manually` | Trace the reported value. Manually translate a display-only field or inner expression first; preserve stored/transmitted values and adjust the display boundary/check appropriately. Do not blindly exempt it. |
| `needs a reviewed client boundary` | Verify client use. Do not add `"use client"` or a translation import to server settings/metadata merely to silence the check; move translation to the client display site. |
| `Built-in metadata changed` | Review source semantics → `i18n:catalog` → review changed summaries/labels. Refreshing snapshots does not update translation meaning. |
| `missing builtin display translations` | Write the reported keys, including new `builtin.tool.<key>.summary` entries, in BOTH dictionaries; sync alone will not create these summaries. |
| `Unsupported…` / duplicate metadata | Review the changed declaration and static parser/tests. Do not remove the check or execute ARTEX tools to inventory them. |
| JSON/placeholder/API failure | Fix duplicate/empty values and placeholder counts. If no working provider is available, use the manual path, not forced wrapping. |

When upstream rewords a string, look for a similar old translation and review its
meaning before reuse. Do not bulk-delete keys absent from extraction: dynamic uses
may remain. Existing translations are intentionally not overwritten automatically.

## Safety and scope

- Extraction and wrapping share one AST inventory. Escapes, comments, JSX entities,
  punctuation-only fragments, numeric JSX entities, nested/multiline templates, and directives use
  the installed TypeScript parser. Nested raw display branches in templates are
  reported for manual wrapping before their parent can be changed; nested existing
  `tr()` calls still participate in dictionary checks. Generated template parameters
  preserve native coercion, comment trivia, and local `String` bindings.
- Automatic positions are JSX text; explicit display attributes such as `title`,
  `placeholder`, `aria-label`, `label`, `description`; toast/alert/confirm and
  error/message setter arguments. Conditional/fallback strings are changed only in
  those positions. Object properties such as `label` or `description` are inventoried
  but require manual review: their names alone do not prove display-only semantics.
- Protocol values (`value`, IDs, names, comparisons, arbitrary templates/setters),
  type declarations, comments, and unknown code contexts are not translated blindly.
  The upload marker is deliberately stable across languages.
- Reuses a safe translation import or generates a collision-free alias. It never
  inserts an import before a directive, wraps an existing translated call, or adds
  client-only translation calls to an unreviewed server module.
- `lib/status.ts` and `navigation/sidebar/sidebar-items.ts` remain raw key maps;
  callers translate labels at render. `config/app-config.ts`, mock data, backend
  messages, user content, and generated text are outside this frontend codemod.
- Invalid dictionaries, HTTP/JSON failures, omitted keys, empty values and changed
  placeholder occurrence counts fail explicitly. All API responses are validated
  before saving; each dictionary is replaced by a same-directory atomic rename.
  Source replacements are atomic per file too. A filesystem/process failure between
  renames can still leave a multi-file run incomplete: re-run extraction/check after
  interrupted runs.
- `--check` verifies this frontend AST inventory, **not** every possible rendered
  string or translation quality. The separate built-in metadata check covers known
  source factories only. Dynamic/indirect text and rich-text sentence grammar still
  require populated rendering checks and human review.
- Built-in tool cards show localized **summaries**, not rewritten model instructions.
  Only exact known defaults match; custom/edited/unknown descriptions stay original.
  Built-in Agent labels are display-only; asset notes require the exact known
  kind/pattern/note tuple plus builtin provenance. Command-rule names remain original
  (including Chinese reserved names): their API has no builtin provenance, and users
  can reuse a reserved name. Rule patterns, IDs, actions, prompts, schema/defaults and save payloads stay raw;
  Chinese may intentionally remain in editable originals or external/user content.

## Backend-free browser check (bounded)

From the root, in a separate browser profile with no real tokens, backend or credentials:

```bash
cd web
NEXT_PUBLIC_MOCK=1 npm run dev -- -p 3917 -H 127.0.0.1
```

Open `http://127.0.0.1:3917` and switch English/한국어 in the bottom-left user menu.
Scope the flag to that dev command; stop with Ctrl+C. Ensure production build
environments and `.env*` do NOT enable `NEXT_PUBLIC_MOCK=1`.

- Mock mode is **not network isolation**. Direct fetch/SSE, downloads and external
  links can bypass the central mock handler. Inspect network requests; do not
  click execution/delete/update/external-connection controls. Exercising those
  needs separate inert localhost fixtures with nonlocal requests blocked.
- Chinese sample task names, logs, reports and user/model content intentionally
  remain original. Mock builtin tool/Agent descriptions may not match the reviewed
  current defaults and therefore remain raw. Do not loosen provenance checks to
  make demo content look translated.
- Empty/disabled mock data hides branches: the model-config usage card requires
  its mock switch enabled; `daily=[]` hides its chart/tooltips. Use separate inert
  examples for uncovered states; do not report them as inspected.
- Inspect new/changed pages, lists, menus, tabs, dialogs and tooltips in BOTH locales.
  Extraction focuses on Han/Chinese punctuation and existing `tr()` keys, so new
  English UI needing Korean translation also needs manual review. Check dynamic
  defaults and custom/edited fallback behavior; compare inert save payloads with
  originals. Demo success is not production database or exhaustive UI coverage.

## Installing the localized fork

Upstream Docker images/releases do **not** contain this fork's patches. Settings →
Version & Updates → Update now / Update to … installs releases from the hardcoded
`Autumn-27/artex` repository in `selfupdate/github.go`. Checking for a version is
not installation; do not install there if you want to keep this UI. If it happens
accidentally, recover with a fork incorporating that upstream version or newer,
not an arbitrary older binary: the database may already have migrated.

Before publication:

- [ ] Record baseline/upstream SHAs; resolve conflicts and review manual display helpers.
- [ ] Pass `i18n:verify`; review both dictionaries and display/original boundaries.
- [ ] Inspect changed EN/KO screens; list uninspected branches and intentional originals.
- [ ] No localization-specific prompt/backend/save-payload changes (distinguish upstream changes).
- [ ] After approval, commit only reviewed files on the update branch and fast-forward
  `main`; if that fails, stop and review. Confirm `origin` is the fork before pushing.
- [ ] Confirm fork `localization-check` CI for the exact SHA. Binary builds/releases
  need separate approval; static UI export is already part of verification.

When building/installing is approved:

1. On the fork, Actions → `build-binary` → Run workflow; select the verified branch
   (`linux/amd64` for Linux x86-64; leave tag blank for artifacts without a release).
2. Confirm the run's source SHA matches the verified commit, then download
   `artex-binaries` with ZIPs and `SHA256SUMS`; verify the ZIP checksum.
3. Stop the service and back up binary, configuration, database and data before
   replacing the binary. Do not overwrite configuration/data. After a DB migration,
   restoring only an old binary is not a safe rollback plan.
4. Check version/SHA, EN/KO switching, embedded UI and PostgreSQL connectivity on
   the actual installation, not the dev server.

The workflow embeds `web/out`; rebuilding the frontend alone does not update an
existing binary. PostgreSQL is still required. Actual artifact execution and WSL1/PTY
compatibility must be validated independently of UI checks.
